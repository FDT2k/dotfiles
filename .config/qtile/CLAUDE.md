# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Linux desktop environment configuration system centered around **Qtile window manager**. Contains dotfiles, shell scripts, and automation tools for a customizable workspace.

## Setup

This directory is part of the dotfiles repo (bare repo with `$HOME` as work tree, see the root `CLAUDE.md`): files are already in place at `~/.config/qtile/`, no symlink or generation step. `config.py` is a versioned symlink to `fdt2k.config.py`, which only contains `from qtile_config import *`.

```bash
# Verify syntax
python3 -m py_compile qtile_config/*.py

# Restart Qtile after config changes
qtile cmd-obj -o cmd -f restart
```

`autostart.sh` is run automatically at Qtile startup by the `startup` hook in `hooks.py` (hard-coded path `~/.config/qtile/autostart.sh`).

## Architecture

### Qtile Config Package (`qtile_config/`)

Modular Python package structure:

| Module | Purpose |
|--------|---------|
| `__init__.py` | Entry point - exports Qtile variables, floating_layout, config |
| `themes.py` | Color scheme integration (`~/.cache/wal/colors.json`, generated by hellwal), `theme` and `theme_neg` classes, WCAG helpers (`contrast`, `mix`, `readable_dim`) for colors computed from the palette (e.g. `theme_neg.inactive`) |
| `commands.py` | Key modifiers (`mod`, `alt`, `ctrl`, `shft`) + script paths (`command.*`, resolved relative to the package as `../bin/...`) |
| `workspaces.py` | Workspaces, rooms, groups, ScratchPad, `workspace_keys` |
| `layouts.py` | Layout definitions (Max, Bsp, TreeTab), widget_defaults |
| `keybindings.py` | All key and mouse bindings |
| `screens.py` | Screen and bar configurations (Battery widget added only when `/sys/class/power_supply/BAT*` exists) |
| `hooks.py` | Qtile hook subscriptions (client_new, startup) |

**Dependency order:**
```
Level 0: themes.py, commands.py (no internal deps)
Level 1: workspaces.py, layouts.py, hooks.py
Level 2: keybindings.py, screens.py
Level 3: __init__.py (imports all)
```

### Workspace/Room System

The Qtile configuration implements a two-level workspace organization:
- **Workspaces** (F1-F6): Top-level context switching
- **Rooms** (a-d): Sub-workspaces within each workspace
- Groups are dynamically shown/hidden based on active workspace
- State persisted across sessions
- **Modular**: `workspace_keys` can be disabled by commenting one line in `keybindings.py`

### Dynamic Menu System

The `bin/` directory uses a `.d` directory pattern for pluggable menus:
- `browser.d/` - Browser selection
- `configure.d/` - Configuration tools
- `power.d/` - Power management (lock, suspend, shutdown)
- `pacman.d/` - Package management operations
- `sound.d/` - Audio output selection
- `worklayout.d/` - Workspace layout presets

`bin/run.sh` reads these directories and presents options via Rofi.

### Color/Theme System

- hellwal generates themes from the templates in `~/.config/hellwal/templates/` (versioned in this repo under `.config/hellwal/templates/`) into `~/.cache/wal/`, in pywal's file formats (`colors.json`, `colors.sh`, `colors`, `colors-rofi-dark.rasi`) plus `terminal.sh` and `dunst-colors.conf`
- `bin/theme/hellwal-apply <image>` is the only hellwal call (appearance options such as `--comfort-mode` live there); it also pushes `terminal.sh` to every open `/dev/pts/*`. It finds the hellwal binary in `PATH`, then `~/.config/qtile/bin/hellwal`, `~/bin`, `~/.local/bin` (Qtile does not read `.zshrc`); the binary is not versioned (`bin/hellwal` is in `.gitignore`)
- The wallpaper is set by Qtile, not by hellwal: `screens.py` passes the `wallpaper` path of `colors.json` to every `Screen` (`wallpaper_mode='fill'`); no wallpaper if the image is missing
- If `colors.json` is missing, unreadable or lacks 16 `#rrggbb` colors, `themes.py` falls back to `DEFAULT_COLORS` and logs a warning: Qtile still starts. Run `bin/theme/hellwal-apply <image>` to get the real theme
- `bin/theme/` scripts apply colors to various components:
  - `pick` - Theme selector (calls `hellwal-apply`)
  - `reload` - Re-apply the current theme (wallpaper read from `colors.json`), then dunst and K70
  - `colorize-dunst` - Restart dunst; its colors come from the drop-in `~/.config/dunst/dunstrc.d/50-hellwal.conf` (link to `~/.cache/wal/dunst-colors.conf`), its settings from `~/.config/dunst/dunstrc`
  - `colorize-k70` - Keyboard RGB

### Monitor Configuration

Screen layouts are per machine, in `bin/screenlayout.d/`, named after `uname -n`:
- `{hostname}.sh` - default layout (`daoloth.sh` desktop, `abhoth.sh` laptop); `{hostname}_{name}.sh` - variant `{name}` (e.g. a portable screen), saved with arandr
- `bin/screenlayout` - rofi menu "Monitor Layout" (`mod+alt+l`): `default`, the variants of the current machine, `arandr`; `bin/screenlayout --default` applies `{hostname}.sh` (nothing if absent)
- applied before the login by SDDM (`screenlayout.d/sddm`, a script running `screenlayout --default`: do not rename it) and at session start by `autostart.sh`

## Key Files

| File | Purpose |
|------|---------|
| `qtile_config/` | Modular Qtile configuration package (see Architecture) |
| `config.py` | Qtile entry point: symlink to `fdt2k.config.py` |
| `fdt2k.config.py` | Target of `config.py`, one line: `from qtile_config import *` (was the monolithic config before the `qtile_config/` package) |
| `autostart.sh` | Desktop initialization and daemon startup (called by the `startup` hook) |
| `bin/run.sh` | Rofi-based application/menu launcher |
| `bin/lock` | Screen locking (uses i3lock-multimonitor) |
| `bin/*volume`, `bin/mutemic` | Audio control scripts (output volume and mute, microphone mute on `XF86AudioMicMute`, which also sets the ALSA capture switch so that the micmute LED follows) |
| `bin/brightnessup`, `bin/brightnessdown` | Backlight ±5% with `brightnessctl` (laptop brightness keys), with a dunst notification |
| `widgets/bluetooth_widget.py`, `widgets/network_widget.py` | Rofi menus (bluetooth `mod+b`, network); they import `widgets/rofi.py`, a vendored copy of `python-rofi` (MIT): keep it, nothing to install |

## Dependencies

Core: qtile, rofi, xrandr, ImageMagick, pamixer, pactl, hellwal, terminator

`bin/install-arch-deps.sh [rofi|theme|lock|dunst|terminator|screens|fonts|activitywatch|sound|bluetooth|xpra]` installs the Arch packages of these groups (all by default), from the official repositories only: no AUR. Tools that are not packaged are built from git by `git_install` (recipes at the top of the script): cloned in `~/.local/src/<name>`, pulled, built with `make` and copied to `~/bin/<name>` on every run. Tools published as GitHub release archives are installed by `release_install` (recipes at the top too): latest release unzipped in `~/.local/opt/<name>` (skipped when `.version` holds the latest tag), binary linked in `~/bin` — ActivityWatch (`aw-qt`, group `activitywatch`). The group `sound` installs PipeWire with `pipewire-pulse`, `wireplumber`, `pamixer`, `pavucontrol` and enables their user services (`systemctl --user enable --now`): without `pipewire-pulse` running, the volume scripts fail with `Connection error`. The group `bluetooth` installs `bluez`, `bluez-utils`, `blueman` and enables `bluetooth.service`. The group `xpra` installs `xpra`, plus `xorg-server-xvfb` on daoloth (`uname -n`), which hosts the Forest session of `~/.shell/forest.sh`. hellwal comes from the fork `https://github.com/FDT2k/hellwal.git`; the script warns when another hellwal (`~/.config/qtile/bin/hellwal`, PATH) would shadow `~/bin/hellwal` for `hellwal-apply`. It is extended group by group, as machines are set up. The group `sddm` is never installed by default (`install-arch-deps.sh sddm`): it installs SDDM, writes `/etc/sddm.conf.d/10-dotfiles.conf` (theme `fdt2k-dark`, `DisplayCommand=…/screenlayout.d/sddm`) and links `/usr/share/sddm/themes/fdt2k-dark` to `~/.local/share/sddm/themes/fdt2k-dark`; it warns when the `sddm` user cannot read the home, without changing permissions. The theme targets the Qt 6 greeter (`QtVersion=6` in `metadata.desktop`, `Qt5Compat.GraphicalEffects`); the group installs `qt6-5compat`, `qt6-svg`, `qt6-virtualkeyboard`.

## Keybinding Conventions

Defined in `qtile_config/commands.py` and `qtile_config/keybindings.py`:
- `mod4` (Super) - Primary modifier
- `mod1` (Alt) - Secondary modifier
- Workspace switching: mod4 + F1-F6 (defined in `workspaces.py`)
- Room switching: mod4 + a/s/d/y/x/c (defined in `workspaces.py`)
- Layout control: mod4 + various keys
- Mouse bindings: mod4 + mouse buttons (defined in `keybindings.py`)
- Call `qtile` object commands without the old `cmd_` prefix (`qtile.spawn`, `qtile.to_screen`, `qtile.restart`): the `cmd_*` aliases are gone in qtile 0.37, the unprefixed names work on 0.34 and 0.37
